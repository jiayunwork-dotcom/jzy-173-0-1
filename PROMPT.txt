隔壁热处理实验室的师兄在带《材料科学基础》的实验课，每年都要批改一百多份“平衡冷却过程分析”作业：给一张二元相图和一个成分，让学生写出冷却时依次经过哪些相区、在某温度下各相成分和相对量、共晶温度以下初生相和共晶组织各占多少。学生用杠杆定律算错的地方五花八门，师兄想要一个后端给出标准答案，还能批量核对学生提交的数值。我把需求记下来，想请你实现。

相图的表示：服务只处理简化的二元相图，成分用 B 组元的质量百分数（0 到 100），温度用摄氏度。支持两类：匀晶相图（液相线和固相线各为一条从 A 熔点到 B 熔点的折线）；共晶相图（两条液相线分支，α 与 β 两侧的固相线和固溶度线，共晶水平线及共晶点）。所有线段用折线顶点给出。相图保存为具名的“相图档”，存成数据目录下的 JSON 文件，可以增删改查。保存时要做一致性校验：液相线不能低于对应的固相线，各线在共晶点、熔点处必须相接，折线之间不能交叉，共晶点成分必须落在两个固溶度极限之间。校验不通过时返回具体是哪条线在哪个温度出了问题。

单点查询：给定相图档、合金成分和温度，服务判断所处相区（液相、α、β、L+α、L+β、α+β），两相区给出连结线两端的相成分和各相的质量分数；在共晶温度以下，还要把 α+β 拆成初生相和共晶组织两部分的质量分数。温度正好等于共晶温度时，三相共存、相对量不唯一，服务要如实说明，并分别给出紧邻上方和紧邻下方的结果，不能随便挑一个。

冷却路径：给定成分，从液相线以上某温度平衡冷却到室温，服务返回依次穿越的每条相界及其温度、每个相区内各相分数随温度的变化（按调用方给的温度步长），以及刚过共晶温度下方时的组织组成。

批改：上传一组学生答案（每条包含相图档名、成分、温度和学生填写的相区、相成分、相分数），服务逐条与标准结果比较，给出每一项是否在容差内、偏差多少，以及整批的正确率。

下面这些关系是标准答案必须经得起的，测试里逐条写上：两相区内两个相的质量分数之和为 1；各相分数乘以各自成分之和等于合金成分；成分恰好在相界上时，对应的另一相分数为 0；共晶成分的合金在共晶温度以下全部是共晶组织，初生相为 0；两相区内相分数随温度连续变化；把相图左右镜像（成分取 100 减原值，A、B 互换），镜像合金的结果与原结果对应一致；匀晶相图中，液相线以上全为液相，固相线以下全为固相；纯组元（成分 0 或 100）在熔点上下直接从液相变为固相。仓库里放一张数值取整、方便手算的铅锡型示范共晶相图作基准，相关用例都拿它当参照。

遇到下列输入要拒绝，并指出出错的字段：成分不在 [0, 100] 内；温度低于绝对零度；折线顶点温度不单调；相图档不存在；批改答案中缺字段或填了不存在的相区名；冷却温度步长非正或步数超过五万。

技术栈：Go 1.23，HTTP 框架 Echo，不用数据库。代码拆成：相图模型与一致性校验、相区判定、连结线与杠杆定律、组织组成、冷却路径、批改比对、相图档存储、HTTP 层。go test 覆盖以上关系，校验逻辑用表驱动测试。容器镜像的编译环节放在 golang:1.23-alpine，最终镜像换成干净的 alpine:3.20，只带可执行文件，相图档目录挂卷保存。服务只经 HTTP 提供，页面和用户体系都不需要。
